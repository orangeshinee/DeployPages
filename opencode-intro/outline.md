## ═══════ Part 1 · 核心概念 ═══════

### Slide 04 · 三个核心概念
- **标题：** 理解 AI 工具，只需要记住三个词：模型、Agent、Skill
- **2×2 表格：** 模型（大脑）/ Agent（手脚）/ Skill（操作说明书）/ 厨房类比预告

### Slide 05 · 一张图看懂 AI 智能体（全幅深色背景）
- **设计：** 深色背景（#141413），全屏厨房类比大图
- **图片：** `img/kitchen-analogy.jpg`（1536×1024）

### Slide 06 · 厨房类比详解
- **标题：** 十个厨房角色，对应十个 AI 概念
- **10 组映射表格：** LLM=厨师 / Prompt=点单 / Context=厨房信息 / Tool=厨具 / Skill=菜谱 / Memory=经验 / Workflow=SOP / Agent=主厨 / Multi-Agent=后厨团队 / MCP=USB-C
- **底部总结：** Agent = 主厨 + 经验 + 厨具 + 菜谱 + 自主决策

### Slide 07 · 模型 vs 产品
- **标题：** 模型 ≠ 产品。一个是引擎，一个是车
- **2×2 表格：** 模型（大脑引擎，无界面）/ 产品（用户界面）/ 类比（发动机 vs 车）/ 为什么重要（OpenCode 不挑发动机）
- **底部金句：** OpenCode = 车架（Agent 系统）+ 任意发动机（模型）

### Slide 08 🆕 · Prompt 写法 Tips
- **标题：** 不知道怎么跟 AI 说话？记住这个万能公式，三分钟上手
- **2×2 表格，四个公式组件：**
  - A. 任务：告诉它你要什么 ——「把这份会议纪要整理成标准格式」
  - B. 背景：给它上下文 ——「这是供应链部门周例会，参会人：张三、李四」
  - C. 格式：指定输出格式 ——「用表格输出，每行一条待办」
  - D. 约束：给它边界 ——「不要超过一页，用中文」
- **完整示例（brand-tint 背景块）：**「把这份会议纪要整理成标准格式，包含待办事项和负责人，用表格输出，不要超过一页」
- **底部金句：** 好 Prompt = 任务 + 背景 + 格式 + 约束。凑得越齐，结果越准

## ═══════ Part 2 · 认识 OpenCode ═══════

### Slide 09 · OpenCode 是什么
- **标题：** OpenCode 不是编程工具，是一个能帮你操作文件的 AI 助手
- **双栏布局：** 左栏（AI Agent 系统，免费开源，不挑模型）/ 右栏（三种使用方式：TUI / Web / Desktop）
- **虚线框占位符：** 🖼️ 界面截图
- **底部比喻：** DeepSeek 网页版像远程专家，OpenCode 像坐你工位旁的实习生

### Slide 10 · 工具对比（重构）
- **标题：** 五款 AI 工具横向对比
- **4 行主表格：** DeepSeek 网页版 / ChatGPT / **OpenCode（高亮）** / Claude Code
- 🆕 **OpenClaw 独立区块（c2）：** 能做（轻量编码助手，免费开源）/ 不能做（团队协作、Skill 系统、多模型切换）
- **结论：** DeepSeek / ChatGPT 像电话咨询，OpenCode 像上门服务

### Slide 11 · 工作原理
- **标题：** 打开终端、描述任务、它自己翻文件干活——就这三步
- **双栏：** 「你说」 vs 「它做」
- **核心变化：** 你的角色从「动手的人」变成「审核的人」。AI 执行，你保留判断权

## ═══════ Part 3 · 实操案例 ═══════

### Slide 12 · 案例一：需求 → SQL
- **标题：** 把业务需求扔给它，三分钟拿到 SQL 和逐行解释
- **场景：** 数字化看板日常——业务需求描述 → 翻表结构 → 生成 SQL 带注释
- **占位符：** 🖼️ SQL 生成前后对比截图
- **金句：** 关键转变——从「写 SQL 的人」变成「审核 SQL 的人」

### Slide 13 · 案例二：笔记 → 会议纪要
- **标题：** 零散笔记扔进去，按你的模板格式输出完整会议纪要
- **场景：** 关键词 + 数字 + 待办 → 结构化输出（主题/参会人/结论/待办/下次时间）
- **占位符：** 🖼️ 会议纪要生成示例
- **用户证言：** 「以前最怕整理纪要，现在最轻松的就是这一步」

### Slide 14 · 案例三：自然语言 → 流程图
- **标题：** 用自然语言描述流程，十秒生成可直接粘贴的流程图
- **场景：** 文字描述 → Mermaid 代码 → 飞书文档直接渲染
- **占位符：** 🖼️ 流程图生成示例
- **核心：** 比拖拽快十倍，修改成本从「重画」变成「重写一句话」

### Slide 15 · 更多场景（加指令示例）
- **标题：** 这四个场景，你下周就能用上
- **2×2 表格，每格加「试试」示例：**
  - A. Excel 清洗：「把这三个 CSV 合并，按供应商代码去重，保留最新日期的记录」
  - B. 需求文档标准化：「把这份业务需求按标准模板重排：背景/核心诉求/验收标准/优先级」
  - C. 写周报：「这周做了供应商风险分析、上线退货率看板、跟进三个需求。帮写成周报，每项三句话」
  - D. 还能干什么：翻译 · 竞品调研 · 解释 API · 测试用例 · 批量通知……

### Slide 16 🆕 · 踩坑 & 幻觉
- **标题：** AI 不是万能的——三个必须知道的坑，踩过再学就晚了
- **2×2 表格，三个警告 + 安全说明：**
  - ① AI 会一本正经地胡说八道：SQL 跑一下再交，你审核过的才对
  - ② 不要贴敏感数据：外部 API 会发送到云端，公司内网部署的模型更安全
  - ③ 你的角色是审核，不是照单全收：AI 是你的实习生——手脚快但不一定靠谱
  - 🔒 内网安全说明（brand-tint 背景）：公司内网使用自部署大模型，数据不出网络，不存在泄露风险
- **底部总结：** 跑一下验证 · 别贴敏感数据 · 你说了算
